# Dev Control Room 사용 가이드

Dev Control Room은 로컬 Git 저장소의 현재 상태를 읽고, 점검 근거를 남긴
뒤, 승인한 작업만 실행하도록 돕는 Windows용 운영 도구입니다.

## 처음 시작하기

처음에는 저장소 하나와 점검 하나만 끝까지 확인하면 됩니다.

1. `serve`로 로컬 서버를 시작합니다.
2. `프로젝트`에서 `프로젝트 등록 → 폴더 선택 → 저장소 찾기`를 누릅니다.
   찾은 저장소 중 확인할 대상을 고른 뒤 `선택한 저장소 등록`을 누릅니다.
3. `진단`에서 `환경 확인`과 `품질 도구 다시 확인`을 실행합니다. 필수 도구가
   사용 가능인지 확인하고, Agent·Jenkins 설정은 필요할 때만 추가합니다.
4. `개선`의 `지금 점검`으로 현재 상태를 갱신하고, `지금 개선할 것`에서
   먼저 볼 항목을 고릅니다.
5. `작업`에서 Worktree를 고른 뒤
   `기존 점검 찾기 → 제안 적용 → Checkset 만들기 → 적용 → 실행` 순서로
   진행합니다. 실행 전에는 명령·제한 시간·HEAD·원본 digest를 확인합니다.
6. `검증`에서 통과 여부·종료 코드·artifact와 효과 근거를 확인하고, `활동`에서
   등록·점검·계획·실행의 시간순 기록을 다시 봅니다.

저장소 등록과 읽기 전용 점검은 원본 파일을 바꾸지 않습니다. 결과가 없을 때
`검증`의 `예시 화면 보기`를 열면 실제 기록에 포함되지 않는 샘플 흐름을 볼 수
있습니다.

## 화면별 역할

| 화면 | 하는 일 |
| --- | --- |
| 개선 | 열린 확인 항목, 품질 개선 큐, 다음 행동을 우선순위 순으로 봅니다. |
| 프로젝트 | 등록한 프로젝트·저장소·Worktree를 확인하고 범위를 관리합니다. |
| 작업 | 발견된 점검을 기준으로 만들고, 결과와 Action 계획을 검토합니다. |
| 검증 | 반복 실행 가능한 점검, 효과, 사용량, artifact 근거를 확인합니다. |
| 진단 | 필수 도구와 연결한 Provider, Agent Profile, Jenkins 설정을 확인합니다. |
| 활동 | 등록·점검·계획·실행 기록을 시간순으로 봅니다. |
| 사용법 | 실제 버튼 순서, 완료 기준, 화면 간 이동을 다시 확인합니다. |

## 무엇을 자동으로 하고, 무엇을 사람이 결정하나요?

- 자동 확인: Git·Worktree 상태, 점검 명령, 종료 코드, HEAD, digest, artifact
  연결을 로컬에서 기록합니다.
- AI Agent: 필요한 경우 제안과 해석을 돕고, 허용된 범위의 Handoff를 준비합니다.
  점검 기준이나 외부 실행을 대신 승인하지 않습니다.
- 사람의 결정: 제안 적용, Worktree 신뢰, Jenkins·릴리스·정리 실행을 승인합니다.

따라서 이 도구의 핵심은 AI에게 바로 맡기는 것이 아니라, 같은 기준으로 다시
확인할 수 있는 품질 기록과 승인 경계를 남기는 데 있습니다.

## 외부 작업과 Jenkins

Jenkins 연동은 `진단 → 실행 설정`에서 등록합니다. 외부 작업을 실행할 때는
다음 순서를 지킵니다.

1. Worktree와 대상 revision을 확인합니다.
2. 외부 작업 계획을 만듭니다.
3. 화면에서 계획과 digest를 검토하고 Worktree를 실행 대상으로 표시합니다.
4. 사람이 승인합니다.
5. 승인된 계획만 실행하고 결과를 `검증`과 `활동`에서 확인합니다.

MCP의 `jenkins.plan`도 2번까지만 수행하며 Jenkins에 접속하지 않습니다.
`jenkins.trigger`는 이미 사람이 승인한 계획만 실행하고, MCP 스스로 승인할
수 없습니다. 비밀 값과 임의 shell/file-read 기능은 MCP에 노출하지 않습니다.

## 문제가 생겼을 때

- 폴더 선택을 취소하면 등록 화면은 그대로 유지됩니다.
- 필수 도구가 없으면 `진단`에서 설치·경로 상태와 다음 조치를 확인합니다.
- 계획이 오래되었거나 Worktree가 바뀌면 실행하지 말고 새 계획을 만듭니다.
- 실패 결과는 지우기보다 `검증`과 `활동`에서 근거를 먼저 확인합니다.

## 작업을 넘기기 전 확인

UI 변경은 정적 계약 검사, Go 테스트와 vet, Windows 빌드, 실제 로컬 브라우저
확인을 모두 통과한 뒤 전달합니다. 브라우저에서는 모든 화면의 제목·가로 넘침·
사용법 슬라이드 URL 상태·키보드 이동을 확인합니다.
