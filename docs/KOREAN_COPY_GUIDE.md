# 한국어 카피 가이드

상태를 먼저 말하고, 사용자가 바로 고를 수 있는 다음 행동을 한 문장으로 안내합니다. 문장은 짧은 합니다체로 씁니다.

## 원칙

- 상태·라벨·버튼은 명사형으로 씁니다. 예: `환경 진단`, `Provider 상태`, `다시 점검`.
- 설명은 한 문장, 가능하면 20자 안팎으로 씁니다. 예: `선택한 폴더만 읽습니다.`
- 선택 기능의 부재를 장애처럼 표현하지 않습니다. 예: `미설정 · 필요할 때 설정합니다.`
- 실패는 원인과 다음 행동을 분리합니다. 예: `Git을 찾지 못했습니다. Git 설치 후 다시 점검합니다.`
- 색상만으로 상태를 구분하지 않습니다. 상태명과 설명을 함께 표시합니다.
- 내부 구현 용어는 필요한 곳에서만 씁니다. `typed argv`, `revision`, `digest`는 세부 정보에 둡니다.

## 상태 표현

| 의미 | 표시 | 다음 행동 |
| --- | --- | --- |
| 정상 | `사용 가능` | 생략하거나 다음 작업을 표시합니다. |
| 선택 기능 미설정 | `미설정` | `필요할 때 설정합니다.` |
| 점검 전 | `미점검` | `환경 진단` |
| 확인 필요 | `확인 필요` | 원인과 재현 가능한 조치를 표시합니다. |
| 차단 | `차단됨` | 차단 이유와 승인·복구 조건을 표시합니다. |

## 짧은 예시

좋은 표현:

- `Provider 상태` / `Codex 사용 가능` / `Claude 미설정 · 필요할 때 설정합니다.`
- `첫 프로젝트를 등록합니다.` / `폴더 선택` / `읽기 전용으로 저장소를 찾습니다.`
- `마지막 점검 5분 전` / `다시 점검`

피할 표현:

- `시스템이 비정상입니다` — 선택 Provider가 없다는 이유로 전체를 실패 처리하지 않습니다.
- `문제가 발생했습니다. 관리자에게 문의하세요` — 원인과 로컬 복구 방법이 없습니다.
- `지금 확인할 일만 모았습니다!!!` — 과장, 중복 감탄, 긴 문장을 쓰지 않습니다.
